### 页面归属与入口

- 任务中心只显示已受理整理及合法续作。移除全局 Worker 状态、整理发现、手动操作板块、
  新建整理按钮及其独立选库入口；任务自身的固定上下文/就绪/失败证据仍可读。
- 新手动整理只从资源库文件页进入。普通新建/重命名/文本编辑/复制/移动/删除回原库文件页，
  通过“当前页面操作状态”弹窗查看进度、结果及已有允许的恢复；刷新/重启后仍能找回。
  按钮位置、样式、隔离及交互由 Product Experience 的普通文件旅程定义。
- 查询先在后端限定整理总体，再统计、筛选、分页及读取详情；Job/Task 按真实关联去重。
  其他消费者的记录、普通文件操作及管理 API/CLI 能力不会因中心收缩而删除。

### 手动受理与确认

明确提交后先受理任务，规则/元数据/分类/冲突无需先就绪。直接文件只受同源未结束工作和
明确后缀排除的业务检查；文件夹先受理、再有界发现并逐项原子查重/占用。保留文件夹配置的
媒体类型筛选（默认视频）及附件语义，其他扫描规则不能变成额外手动准入门槛。权限、库根、
固定快照、真实稳定性与完整范围校验仍在执行前保证，不能静默执行前 N 项。

识别、元数据、分类、冲突使用原生决定 → 分析 → 精确摘要 → 明确确认 → 真实结果；成功项
不重跑、效果不确定不重放。普通待执行确认在“进行中 / 全部任务”的精确任务界面继续，
刷新/重启后可找回；无四类恢复关联时不计待处理或提前归为已结束。旧准备/未知请求链接
保留原上下文；通用新建 URL 引导 Files，不自动创建工作。

### 四类需要处理与八个视图

保留全部任务、进行中、需要处理、已结束及识别/元数据/分类/冲突四页；删除失败恢复。

- 需要处理/待处理统计只聚合四类当前问题及其必要人工决定/分析/摘要确认步骤。任务跨类型
  去重，各类型保留自己的任务/文件数；仅排队/执行不计人工待办。
- 真正解除问题才移出，保存决定/生成摘要/受理不等于成功。新四类问题换到对应类型；仅剩
  技术失败时退出需要处理，保留真实失败/部分成功及历史。精确关联证明全部工作成功才显示
  “已完成（恢复成功）”，原失败尝试不改写、恢复不重复计数。
- 其他终结失败只在全部/已结束及事实详情、结果、日志、导出中查看原因、阶段和已完成/
  不确定效果；不单独统计失败或提供通用修复/重试/核查指引。Provider 网络错误不因发生于
  元数据阶段就变成元数据决定。旧失败恢复深链只到精确历史/普通不可用，不恢复旧流程。

自动化打开/保存启停、启用执行、运行一次及保留的稳定性处理按 Slice46 RO-5/AC-11–13/17–18；
复用本页四类恢复，不引入普通手动选库入口。完整交互见 Product Experience 自动化旅程。

## 2. 页面结构与共有行为

共享侧栏保留单个“任务中心”入口，八个标签在同一横向导航行：全部任务、进行中、需要处理、
已结束、识别恢复、元数据恢复、分类恢复、冲突处理。默认全部且不打开详情。窄屏可有界横向
浏览标签/表格。任务中心顶部不显示共享 Shell 的通用搜索框；全部任务只保留本机时区的创建
时间范围（可单侧/双侧选择并清除），其他七个视图保留既有搜索、来源、状态、时间、分页、
详情及返回上下文，并保存在合法有界 URL 状态。

主内容区只显示一个“任务中心”页面标题，不再叠加同名页面位置提示。标题层级、内容边界与
留白尺度参照媒体库页协调，列表在桌面首屏可直接阅读；不规定逐像素一致或固定首屏行数。
长名称/范围展示受列宽约束，不能挤走阶段、进度、状态和时间；省略展示仍保留完整原文及
鼠标/键盘可达的详情，选择与请求使用原始任务/路径身份。窄屏允许标签/表格内部有界滚动。

共享侧栏“文件”是普通资源库页面导航，不自动携带任务中心列表来源，也不显示“返回任务中心”；
已有来源的文件页再次点击侧栏“文件”也清除该入口。显式任务、准备记录和整理续作链接仍保留
自身合法的返回上下文，能回到准确任务与列表状态；刷新/重新连接不重提工作。

后端先限定完整获准整理总体，再分组、查询、分页、统计和读取详情：手动已受理整理、定义
定时/运行一次及其合法续作。普通文件/通知/独立分析不进入中心或旧 Task/Job 列表旁路。
只有持久 Job→Task 及恢复关系可去重/关联，不用标签、文件名、时间或今天的 Active 猜测。
预 Task 排队/失败仍在全部/已结束；未知总量、旧记录缺失信息明确标注，不编造零值或成功。

| 视图 | 收录范围 | 动作 |
|---|---|---|
| 全部任务 | 已受理整理及合法续作，包括预 Task 记录 | 精确详情、允许控制、四类处理 |
| 进行中 | 排队、执行、暂停及普通初次待确认等未终结整理 | 进度、后端允许控制、精确摘要确认 |
| 需要处理 | 当前四类业务问题及其仍需人工决定/分析/摘要确认的并集 | 进入当前任务/类型文件处理 |
| 已结束 | 完成、部分成功、失败、取消的整理 | 持久结果；仅当前四类保留处理入口 |
| 识别恢复 | 未解决类型/歧义及后续必需人工步骤 | 合法类型、忽略及安全分析 |
| 元数据恢复 | 候选/检索信息修正及后续必需人工步骤 | 显式搜索、候选/标题/年份修正 |
| 分类恢复 | 分类未命中/目标选择及后续必需人工步骤 | 固定上下文合法目标 |
| 冲突处理 | 目标冲突及后续必需人工步骤 | 许可跳过/重命名/明确授权覆盖 |

四类可重叠，每类保留自己的任务数/文件数；待处理任务总数为去重并集，不能相加。
普通初次确认不是第五类待办。纯排队/运行无人工动作不算 Attention；纯技术/Provider 传输/
Storage/权限/部分/未知效果不是业务类型。它们只在全部/已结束及事实详情/结果/日志/导出中
保留真实状态、失败阶段、原因、已完成/不确定效果，不单独提供失败统计或通用恢复指导/按钮。
旧失败恢复深链不恢复第五类。行政 API/CLI 恢复不因中心呈现收缩而被删除。

## 3. Files 整理：先受理 → 任务内分析 → 精确摘要 → 明确执行

资源库文件页是新建手动选文件整理的唯一正常入口。单/多/文件夹/混合选择明确提交后，先持久
受理固定配置/有界来源的整理 Task，再在 Worker 内发现、真实稳定性观察、识别、元数据、命名、
分类、附件和完整计划计算。直接文件只保留未完成同源占用与明确扩展名排除的业务入口检查；
仅未在扩展名允许列表不等于明确排除。文件夹保留配置的主媒体扩展名（默认视频）和附件语义，
图片/字幕/NFO 不自动成为独立主项或识别问题，未关联文件留原地。媒体库不是整理来源。

文件夹外层 Task 先于遍历；每个发现源在自身准入时原子检查/保留 Storage 精确来源身份。
不同入口、库绑定和并发请求不能重复占用一源；同名不同来源保持独立。Storage I/O 不跨数据库
事务。RBAC/根约束/稳定性/完整范围预算仍生效，实质边界导致范围不完整时不得执行前 N 项。
单项读取/准入拒绝保留自己的原因；未受影响的已知合法兄弟仍可在精确摘要中明确选择。

Files 可有界找回精确已提交工作、单独/既有准备及丢响应请求。关闭、刷新、重连不重发命令。
普通泛化 new URL 只引导 Files；有效既有准备/任务续作深链保留原身份，不能猜测另一个库/请求。
浏览/独立分析不制造整理任务或执行意图；明确受理任务内的四类发现进入原生恢复。

同界面摘要显示来源/范围/完整性、主文件/附件及就绪/未就绪/排除原因、操作与目标媒体库/目录、
逐项来源→目标、识别/元数据/策略解释、附件清单、能力/冲突/覆盖/删除/源清理影响。
普通初次摘要确认在 Running/All 的精确任务上下文中持续可达，刷新/重启后仍可打开。

“确认整理 N 项”只确认选择的合法就绪子集；附件/覆盖/清理许可绑定该子集实际影响。
后端原子校验计划/来源/版本/pin/主体/选择/独立效果许可；Worker 在 fence 下交 OrganizerExecutor。
未选择/未就绪项保留独立状态，分析/保存决定零媒体变更，实质来源/方案变化需更新摘要和意图。
响应未知先精确核对已有持久请求；不猜最近任务、不自动重发或传递原始 token。

## 4. 四类恢复：决定 → 分析 → 摘要/确认 → 真实结果

类型列表按完整授权总体聚合，一任务一行；打开后为精确任务+类型的有界文件处理，展示该项
原因/阶段、来源/目标、已完成步骤、效果确定性及后端合法动作。类型输入分别使用识别类型选择、
Metadata 候选/标题/年份/类型修正、合法分类目标、冲突跳过/重命名/许可覆盖。搜索 Provider 必须
显式操作；读页面/刷新不查询 Provider。复用 Naming A/Classification A 不改变 RecognitionType C。

保存决定不执行，随后只对允许项重新分析。分析进度/结果与原项通过持久关系关联，原 pin 不可用
则拒绝，不静默改绑 Active。遇新四类阻塞转入其当前类型；纯技术后续失败移出 Attention，保留
新旧真实结果。成功/忽略/跳过/取消和未知效果不能作为普通失败自动重跑。

分析得到合法计划后在当前处理界面显示精确可继续文件/附件/剩余步骤、来源/目标/策略解释、
不会重复的已完成步骤、仍拒绝项及覆盖/清理影响。显式“确认继续整理 N 项”才授权精确选择；
仅保存或分析完成不解决整个旅程，仍需人工操作时保留原四类 lineage，不能丢失摘要步骤。
排队/运行后续不凭空维持人工待办；独立已受理/拒绝项各自返回结果，重复/并发/丢响应不重复准入。

确认受理或 Job 完成不是恢复成功。按精确关联的已验证真实效果更新成员/计数；全部必要项均
证明整理成功才显示“已完成（恢复成功）”。原失败尝试不改写，恢复不重复计数。混有技术失败、
忽略、跳过或未知效果时移除已解决业务待办，但不虚假显示全成功。原成功兄弟不重放，主文件
已完成而附件失败保留完成及附件独立证据；不增加附件专用自动恢复、跨任务批量变更或通用回滚。

返回/深链/刷新/重连恢复原类型/筛选/分页；过期决定重读合法选项，拒绝保留可修正输入。
无证据的历史效果仅事实读取，不由恢复页赋予重试/强制执行权。

## 5. 详情、控制与持久结果

中心精确详情提供阶段、主文件/附件处置、来源/目标、策略解释、持久结果、相关日志/审计、
恢复链和有界脱敏 JSON 导出。日志不是结果存在前提。旧 Task/Job 精确链接将整理定位到中心
当前真实运行，普通操作定位到其已证明的原库本地状态；缺失/拒绝/不可用给出有界只读说明。

仅展示后端允许的协作暂停/继续/取消；区分请求与已生效，不中断在途调用或声称回滚。
任务局部 Worker/pin/权限事实保留，移除全局 Worker、发现和手动操作块及其独占读取/轮询。
读取、统计、刷新、导出不准入工作、不查询 Provider 或改变媒体。可见活跃页有界轮询，隐藏停止；
写命令不自动重试。普通文件“当前页面操作状态”由两种库页各自提供，不增加全局操作中心。

## 9. 实现约束与验收依据

共享 Shell、查询/分页/返回上下文和合适的专用表单；应用层决定当前合法动作与恢复语义，
