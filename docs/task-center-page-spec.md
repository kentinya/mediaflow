## 2. 页面结构与共有行为

共享侧栏保留单个“任务中心”入口。九个标签在“全部任务”所在的**同一横向导航行**，
点击即进入相应的独立列表页面；不先选一个任务，不新增侧栏“恢复中心”。

默认进入“全部任务”，不打开任务详情。标签、搜索、来源、类型/状态、时间及有界分页具有
可深链、刷新和重连后恢复的 URL 状态。窄屏允许标签栏有明确的横向滚动，不能藏掉某一类恢复。
统计卡片、列表列和提示随当前页面的查询范围变化；任务数与文件数明确区分。

列表一行代表一个后端确定的工作单元。Job 与其显式关联 Task 去重；排队中、尚未生成 Task
的失败和独立 Task 均可见。恢复尝试保留原项和续作关联，不能靠文件名、时间接近或当前配置
推测关联。一次运行结束的历史结果不会因为恢复成功而被覆盖；当前待处理状态按真实记录更新。

| 标签 | 收录范围 | 主要动作 |
|---|---|---|
| 全部任务 | 已受理和历史工作，包含现有文件维护/传输结果 | 查看详情、进入处理；新建仅整理 |
| 进行中 | 正在排队、执行或处于可继续暂停状态的未终结工作 | 查看进度、后端允许的暂停/继续/取消 |
| 需要处理 | 真实存在未解决决策、失败修复、效果核查或其他明确人工动作的工作 | 定位问题及相应处理界面 |
| 已结束 | 已完成、部分成功、失败和取消的运行 | 查看结果；仍有问题时保留处理入口 |
| 识别恢复 | 有未解决识别类型选择或识别歧义的任务 | 确认合法类型、忽略等现有允许动作 |
| 元数据恢复 | 有未解决候选选择、匹配失败或检索信息修正的任务 | 选择候选、修改标题/年份/类型、按需搜索 |
| 分类恢复 | 有分类未命中或合法目标待选择的任务 | 选择允许的分类结果或修复分类规则 |
| 冲突处理 | 有文件/附件目标冲突的任务 | 按许可跳过、重命名或明确授权覆盖 |
| 失败恢复 | 有尚需修复、继续或人工核查的失败项的任务 | 修复条件、继续安全范围或只核查 |

标签是可重叠的查询视角。一个任务可一边处理其他文件，一边出现在恢复页；部分成功或失败
的运行也可同时属于“已结束”和“需要处理”。普通排队本身不等于需要人工恢复。
“需要处理”应依据当前真实问题和允许动作，而不是沿用所有 Pending/Paused 状态一律报警。

任务名称以稳定业务名称和历史范围为主，不以 UUID 拼接操作名充当名称。旧记录缺少名称、
阶段、总量或解释时明确显示不可用，不读取今天的 Active 配置改写旧结果。进度表示已处理量，
不充当成功率；发现总数未知时保持不定量，不编造剩余时间。忽略、等待、部分和效果未知
不得计为整理成功。

## 3. 新建整理：同页计划摘要 → 确认执行

### 用户目标与入口

在任务中心点击“新建整理任务”，选择 Active 资源库及安全的目录/文件范围，查看这次
整理的实际方案，再明确执行。Files 页单项、多项和文件夹整理复用相同应用行为并保留返回上下文。
MediaLibrary 不成为整理来源。创建界面可用资源库目录选择器，无需普通用户复制 Storage 路径、
FileIndex 标识或内部授权材料。

### 准备与摘要

用户明确请求生成摘要后，系统执行有界发现、过滤、稳定性观察、识别、元数据、命名、
分类、附件与完整计划计算。长操作通过现有持久任务/队列/Worker 完成，显示准备进度；
没有独立 Scan 或 Preview 产品模式，也没有独立 Preview 页面跳转。

摘要嵌在当前创建界面，至少显示：

- 来源资源库、所选范围及发现是否完整；
- 可整理主文件数、关联附件数、未就绪/待处理/被排除项及原因；
- 各项 Move/Copy/HardLink/SoftLink，目标媒体库及目录；
- 可展开的逐项“来源 → 目标”、识别/元数据/策略解释及附件清单；
- 已存在目标、能力限制、覆盖、删除/来源清理等准确影响；
- 当前可确认的精确范围，以及不允许执行时的原因和下一步。

准备、读取摘要和保存选择均零 Storage mutation，不产生执行授权，不制造必须解决的
正式执行 Review/Conflict 待办（保留 REQ-ORG-011）。未就绪项保留独立可查看的准备状态和补正入口，
不能伪装为已执行失败；只有已明确受理的整理尝试产生的真实待处理记录进入正式恢复清单。

### 确认与结果

按钮按实际范围显示“确认整理 N 项”。用户可明确选择就绪子集；附件、覆盖和清理权限必须绑定
该子集及其实际影响。未选择/未就绪项保留自己的状态，不能被假定为成功、忽略或自动加入后续执行。
没有可执行项或完整性受实质边界影响时，不提供可执行的前 N 项假成功。

确认是独立于分析的执行意图。后端原子地校验精确计划、选择、版本、来源、配置快照和权限，
防止重复准入与重复消费授权；执行由现有 Worker/OrganizerExecutor 承担。来源或影响方案发生实质
变化时回到当前界面更新摘要并再次明确选择，不自动执行新方案。单纯更新当前 Active 不改绑
合法的历史固定快照。

成功受理立即有可查询的运行身份和返回任务中心入口；每文件结果及附件步骤独立保存。
响应丢失先核对精确请求的持久状态，不猜测最近任务、不自动重发。禁止命令行 token 复制或
另开 Preview 作为普通 Web 完成步骤。

## 4. 按恢复类型跨任务聚合，按任务内文件处理

每个恢复页独立搜索、筛选、统计和分页，覆盖当前账号可读的完整任务总体。一个任务在同一类型页
只占一行，显示历史业务名称/来源、该类问题摘要、涉及文件数、更新时间和当前动作。
同任务的不同文件可进入不同恢复类型；已解决的旧阻塞不能因为历史失败记录仍在而重新出现。

点击行内动作后进入“该任务 + 该恢复类型”的原生文件处理界面，展示本类型的逐项原因、已完成效果、
安全性及允许动作。识别、元数据候选/纠正、分类、冲突分别使用适合的表单；失败恢复明确区分
可安全继续、需修复配置和只能人工核查。已有任务内有界批量分析恢复保留逐项准入/拒绝结果；
本版不新增跨任务批量执行或批量覆盖。

保存决定可组合安全分析步骤，随后在当前处理界面显示新的计划摘要，再明确确认可执行范围。
不跳到独立 Preview，不以“保存决定”直接取得变更权限，不额外要求用户操作内部 DryRun Task。
后台可保留必要耐久分析记录与续作关联；通用 DryRun 功能不因此被整体删除。

处理后按后端真实待处理状态更新该类型列表及计数；仍有其他问题的任务保留，新增不同阻塞进入
相应类型。返回、刷新、重连及直接深链保留来源类型、筛选和分页；过期决定要求重新读取当前合法
选择，失败保留可修正输入。未知提交结果先核对，效果不确定的真实变更只核查，不自动重放。

分类只能选择当前固定上下文允许的目标；复用 A 命名/分类策略不改变 RecognitionType C。
冲突中的覆盖与来源清理需要策略许可和明确影响确认。成功、忽略及未知效果项不会被失败项恢复
自动重新纳入执行。

## 5. 详情、控制与持久结果

列表的查看详情进入原生任务详情，提供阶段、主文件处置、附件步骤、源/目标、策略解释、
持久结果、相关日志/审计、恢复链及有界脱敏 JSON 导出。日志补充结果，不作为结果存在的前提。
现有 Task/Job 深链接可继续解析到真实记录，普通入口不再要求用户区分两套管理页面。

暂停、继续和取消只展示后端对当前对象真实允许的动作；区分已请求与已生效，说明在途调用，
不声称立即回滚。继续重验剩余安全范围及实际执行权限，不复用已消费一次性许可或已撤销的
无人值守许可。不可直接继续时，在同页走必要的摘要与确认。

显示实际 Worker 就绪/等待/固定快照不可用等原因和具体动作。读取、统计、刷新、导出、标签切换
无工作准入、Provider 调用或 Storage mutation。活跃页面采用有界可见轮询，隐藏页面停止轮询；
所有写命令禁止自动重试。

## 6. 独立 Scan 的完整退役边界

移除独立 Scan 的 Web 页面/按钮、API/CLI 创建命令、独立排队执行与重试/续跑分支，以及仅由这些
入口消费的服务和代码。不能藏在“更多操作”、diagnostic 名称或旧入口后保留可运行的独立 Scan。
旧命令请求明确返回已退役和新整理入口指引，不把旧扫描默认为真实整理。

保留实际供整理使用的 Scanner、资源发现、过滤、临时文件排除、稳定性及 Storage 抽象。
组织/自动化共用的稳定性路径不得再要求用户先发起已退役的独立 Scan；需要的观察由其原流程内部
有界完成，不能降低稳定性要求。旧 Scan 数据、结果、审计和正在运行的已知效果保留；
退役不能删除媒体或静默重放存量工作。旧未完成独立扫描安全停止并提供历史查看/取消指引。

定义绑定的 Automation 模式退役、全局引擎设置与自动化页面整体重构仍归冻结 Slice43；
本 Slice 只处理上述独立 Scan 和共享稳定性依赖，不导入或宣称交付冻结实现。
规则测试、通用诊断 Preview/DryRun、既有历史读取以及其他未选页面保留。

## 7. 实现约束与验收依据

前端共用 Shell、列表/筛选/分页和返回上下文组件，用各视图配置及专用表单组织九页；
Python 应用层负责当前允许动作、恢复分类和共享编排，Repository 提供完整授权总体上的一致查询。
不得前端拉若干页再拼成跨任务恢复列表，也不得新建另一套执行队列、恢复引擎或配置权威。

Task 状态、文件结果、当前问题与执行效果确定性分别建模；原始 Job/Task/TaskItem/Result
及恢复记录通过真实持久关系投影。必要迁移只允许保留历史意义的增量变更；不得把旧扫描、
DryRun、忽略或未知结果改写成整理成功。API 与 Web 使用相同权限、校验、状态及安全边界。

验收覆盖九个原生列表/深链/重连、全总体计数和跨页筛选、同任务多类型与逐项解除、就绪子集
计划确认、来源变化和重复/丢响应准入、各类恢复、协作控制及 Worker 重启/配置固定、零变更分析、
未知效果不重放、独立 Scan 退役及历史读取。实际测试分工和证据执行遵循 SLICE.md 与 B 的 Task，
不能以概念图或文档状态代替已运行证明。
