# Slice Owner / Architect / Final Reviewer 经验

通用经验参考；具体权限、安全和验收以所在项目的规则为准。
- **先定用户结果。** 围绕完整用户旅程划定 Slice，再选择实现机制。
- **区分必要与增强。** 普通正确性和安全不能省；低概率的增强恢复按后果、成本和替代路径取舍。
- **选择最小机制。** 优先复用已有能力；可安全重算的阶段，保留状态并停止旧尝试后可显式重做，不必承诺所有异常无缝续跑。不确定的真实变更不能自动重放。
- **范围变化要明确。** 减少恢复义务也会改变验收；由范围负责人修改并提交 Contract，再重新评估 Task。延期不能记作已交付。
- **分开评估复杂度。** 设计承诺、现有耦合、跨层实施和验证风险分别看；范围变小不保证代码或测试成本同步下降。
- **按当前约定收尾。** 审查整个 Slice 的实际改动与用户旅程；可选证明、非阻塞优化和已声明延期不阻止完成，安全与必需结果仍须满足。
- **严重性要看实际可达性。** 注入接口能证明防御缺口，但不能单独证明现有适配器事故概率；结合真实入口、后果和替代路径定级，出现具体可达证据再重评。

每个 Slice 完成后复盘，只补充 1–3 条值得复用的新经验，以“问题 → 做法 → 适用条件”一句写清。
合并重复、替换过时内容，始终保留短清单；不记项目历史、提交号或测试计数，没有新经验不凑数。
