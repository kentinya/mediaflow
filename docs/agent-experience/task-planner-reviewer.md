# Task Planner / Task Reviewer 经验

通用经验参考；具体权限、安全和验收以所在项目的规则为准。

- **按完整行为规划。** 从已提交的 Slice 范围出发，覆盖必要层次，不按文件、字段或单个测试拆任务。
- **反复返工先找根因。** 检查跨层语义、过强的恢复承诺和任务边界，避免继续叠加补丁或通用框架。
- **范围问题交还负责人。** 不能通过改测试或 wording 减少义务；新 Contract 提交后，明确判断 Task 是继续、调整还是重规划。
- **测试按风险安排。** 先跑失败案例和受影响测试，再完成约定门槛；复用匹配的证据，避免无理由重复全量验证。
- **审查真实链路。** 核对实际改动、运行路径与证据；配置要验证发布到消费，用户功能要验证真实入口，测试数量不代表完成。
- **满足结果就停止。** 每次 Task 通过后检查全部 Slice 要求；满足就交最终审查，不为可选证明、文案或非阻塞清理继续造任务。

每个 Slice 完成后复盘，只补充 1–3 条值得复用的新经验，以“问题 → 做法 → 适用条件”一句写清。
合并重复、替换过时内容，始终保留短清单；不记项目历史、提交号或测试计数，没有新经验不凑数。
