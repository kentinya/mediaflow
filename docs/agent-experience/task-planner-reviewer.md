# Task Planner / Task Reviewer 经验

通用经验；权限、范围和测试分工以 [Development Workflow](../development-workflow.md) 为准。

- **按完整行为规划。** 从已提交 Slice 或用户授权的独立 bug 范围及真实代码缺口出发，复用能力、覆盖必要层次，不按字段或单个测试拆 Task。
- **返工先查根因和用户影响。** 从真实请求和完整操作判断产品结果，再确定返工范围；脚本报错保留运行事实，未定位问题由 B 继续核对，不扩成产品返工或测试工具开发。Contract 有问题交 A，修订提交后明确继续/调整/重规划。
- **验收自己负责。** Developer 交受影响测试结果，B 对精确候选跑全量/原生/安全验收；先复现已知阻塞，再跑昂贵门禁，匹配结果不机械重复。
- **审查真实链路。** 配置验证发布到消费，功能验证真实入口；未知提交要组合“原效果完成后再修改兄弟方案”核对原请求与交接，测试数量和报告标签不能代替用户结果。
- **共享逻辑检查各入口。** 显式选择、遍历、分页可能语义不同，用原生输入核对最终清单、摘要和实际结果。
- **按可见结果验收界面。** 重复页面提示可能只是普通文本，不能只数 heading；检查主内容区的可见层级并排除正常侧栏入口。布局用同视口截图、可读性和溢出验证，避免把 CSS 数值或 DOM 形态当成唯一结果。
- **并行浏览器验收分开产物目录。** Node／真实 Python Playwright 同时使用默认输出目录会相互清理 trace；并行时指定独立目录，保留原失败日志，产物冲突修正后按原断言重跑对应套件。
- **返回要核对地址和重开。** 取消浏览器后退后，同时检查原地址、草稿和刷新／认证后的同一耐久上下文；仅见弹窗仍在不能证明恢复，适用于路由内弹窗。
- **满足就停止。** Task PASS 后核对全部 Slice 结果；满足就交 A，不为可选证明、文案或 P2 清理继续造任务。

收尾时仅保留少量问题→做法→适用条件的可复用经验；合并重复，不记流水账，无新经验不凑数。
