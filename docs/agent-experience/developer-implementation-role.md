# Developer — Implementation Role 经验

通用经验参考；具体权限、安全和验收以所在项目的规则为准。

- **开发期与验收期分开验证。** 迭代时只跑受影响测试，实现完成并冻结候选后再执行完整门禁；修复后只重跑受影响部分，避免提交前后重复全量。
- **独立门禁并行执行。** 互不依赖的测试、构建和容器验证同时启动并统一收集结果，用最长单项而非各项之和决定等待时间；前提是各门禁使用独立端口、项目名和临时目录。
- **大套件按模块分片。** 用例集中的套件分片并发执行可显著缩短墙钟时间；分片只改变执行方式，覆盖范围须与单次全量一致。
- **环境类失败一次就查清。** 挂载、路径、权限失败先定位宿主或运行环境约束并固定所需变量，不当作偶发问题重试，否则每次都要重付昂贵的准备成本。
- **不为省时削减约定门禁。** 优化只针对执行次数、并行度和分片，测试等级要求的覆盖与证据必须完整保留。
- **既有失败先在父版本复现再上报。** 与本次改动无关的失败，在父版本独立复现并留下证据，标注为既有问题交审查方判断，不自行认定其不影响验收。

每个 Slice 完成后复盘，只补充 1–3 条值得复用的新经验，以“问题 → 做法 → 适用条件”一句写清。
合并重复、替换过时内容，始终保留短清单；不记项目历史、提交号或测试计数，没有新经验不凑数。
