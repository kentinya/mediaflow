# Developer — Implementation Role 经验

通用经验；权限、范围和测试分工以 [Development Workflow](../development-workflow.md) 为准。

- **草稿保留原读取配对。** 按身份、类别、模式和对象隔离输入，同时保存产生它的读取基线；恢复后若当前值已变，只在明确采用或复核时一起更新输入、基线与表单上下文，适用于可刷新／重认证的配置弹窗。
- **位置迁移保留输入。** 证据改为行内展开时，筛选／分页可能重新挂载表单；把既有决定草稿放在稳定的任务／账号边界内，复用检查点归属，并从真实编辑→筛选→返回入口验证输入，适用于列表内外切换的表单。
- **异步命令固定输入。** 提交时捕获完整请求身份，发送和未知结果核对共用它；可编辑的新方案独立推进，适用于提交后仍允许兄弟修正的旅程。
- **先验证本轮影响。** 新增/修改用例、失败复现和直接受影响回归通过后交候选；全量验收由 B 执行，不把门禁日志整理当成开发主任务。
- **反复失败先找根因。** 跨层语义、环境路径/挂载/权限先定位再修，保留实际失败，不用重复重试掩盖问题。
- **交接要可定位。** 给出精确 checkpoint、实际受影响测试结果和剩余风险；未验证不写通过，既有失败先在父版本复现。
- **包装核对真实输入。** 涉及构建时防止旧 staging 带入已删除模块；向 B 说明产物来源和改动，适用于 wheel/镜像交接。

收尾时仅保留少量问题→做法→适用条件的可复用经验；合并重复，不记流水账，无新经验不凑数。
