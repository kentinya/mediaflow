extends the frozen V1 requirements baseline without renumbering its `REQ-*` or `UX-*` entries.

they preserve historical V1 meaning and all safety invariants. See `V2-AUTO-009` and the amendment
in [`requirements.md`](requirements.md). Slice-specific architecture and proof details
remain in [`SLICE.md`](../SLICE.md) and the architecture document; this file records only durable
product and authority boundaries.

## Task flow status and Automation success rate — TARGET (Slice48 PLANNED)

The user selected this amendment and requested Slice planning on 2026-11-03.

| ID | Requirement | Acceptance meaning |
|---|---|---|
| V2-TASK-012 | Task has five current flow states: pending, running, completed, failed and cancelled. | Flow state is independent of stage, waiting reason, queue eligibility, file/attachment/operation result and read availability. Partial-success and paused are not current Task states; Pause remains retired. Required human/machine work stays unfinished, with visible waiting. Missing/unreadable Task-state truth is unavailable, not a fabricated sixth status or a guessed valid state; missing file results remain independent. Shared Task consumers, including ordinary-file aggregates on both library kinds, use this vocabulary without replacing their per-operation results or queues. |
| V2-TASK-013 | Only failure of the Task flow itself makes the Task failed; ended file-processing technical failures count as completed. | Normal closure and ended file technical attempts yield completed regardless of failure/partial/skip/ignore/individual cancellation, unknown effects or missing formal file Results. Actual file results, effect verification and remote-stop proof are not completion gates. Keep known steps/failures and missing-result truth; do not invent success. Required human steps, genuine remaining machine work and a locally executing call remain unfinished; a stale marker from the ended failed attempt alone does not keep Task running. Incomplete scope/root discovery, broken required context/relations or fatal Task orchestration still fail the Task, never inferred merely from a file failure or absent Result. Persist Task closure under existing fences; absence of a file Result alone cannot retain an ended Task's ordinary queue slot, while live-effect protection and uncertain non-replay remain. Task-status publication failure preserves last durable truth. Explicit safe cancellation remains distinct. |
| V2-TASK-014 | All affected consumers distinguish flow completion, file outcomes and real recovery. | Task Center's eight views/counts/detail, Files local ordinary-operation status, Dashboard, API/CLI/log/export and existing Task-status consumers expose consistent flow state and independent processed/success/partial/failure counts. Completed means the flow ended, never all files succeeded or an uncertain effect was verified. Four-type waiting/decision/analysis/summary/explicit continuation remains in the same Task; completion alone neither clears a business problem nor proves recovery success. Legal explicit continuation may re-enter the current Task without replacing original outcomes/pins or creating generic technical/attachment retry. Latest formal file failure/partial still drives automatic history exclusion and new-manual warnings even when Task is completed. |
| V2-AUTO-012 | Automation success rate and execution-record Task results use Task flow outcomes. | The authorized cohort includes Scheduler due AND the Automation definition's Run once; Files/CLI manual organizing and ordinary file operations are excluded from numerator and denominator. Rate is completed/(completed+failed+cancelled); pending/running are excluded, cancellation is not successful, and zero ended/unavailable evidence yields no percentage. Each original Task counts once through legal same-Task continuation. Remove successful-primary/all-file/attachment/effect-certainty/Result-presence predicates and frozen file-derived stage substitution. Task completed under V2-TASK-013 counts as success, including file technical failure with unknown effects or no formal Result. Records/status filters/counts/paging use the same current Task flow state as Task Center within their own authorized population; ten failed files can coexist with completed flow. Preserve original times/attempts/file effects, compact read-only records, truthful file/no-work/exclusion evidence, local-month/timezone and unavailable states. Missing file results are not missing Task truth. This amends V2-AUTO-006 result/filter meaning without new recovery controls or history rewriting. |
